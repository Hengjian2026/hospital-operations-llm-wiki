# 医院运营管理数据分析知识库 (Hospital Operations Data Analysis Knowledge Base)

## 概述 (Overview)
这是一个关于**医院运营管理数据分析**的开源知识库，基于 LLM Wiki 模式构建。本知识库汇集了医院各科室的 DRG/DIP 病种分析、绩效考核、财务分析等报告，并通过大语言模型（LLM）进行增量维护，以提取跨文档的关联和深层洞察。

## 免责声明 (Disclaimer)
**注意**：本知识库中包含的所有数据均为合成、模拟或经过严格脱敏处理的数据，**不包含**任何真实的患者个人隐私信息或医院真实的敏感运营数据。本项目仅供学习、研究、代码演示和方法论探讨使用。

## 目录结构 (Folder Structure)
本知识库采用结构化的目录编排，既方便人类读者阅读，也便于 LLM 代理理解和维护：

- `CLAUDE.md`: 核心 Schema 定义与系统提示词（LLM 维护指南）。
- `index.md`: 知识库的总索引入口，提供自顶向下的导航。
- `log.md`: 操作日志，按时间记录文档的摄入和重大更新。
- `raw/`: 原始文档存放区（只读）。
  - `doc/`, `docx/`: 原始文档和分析报告。
  - `mp4/`: 原始视频文件。
- `wiki/`: 由 LLM 生成并维护的结构化 Wiki 页面。
  - `来源/`: 原始文档的结构化提炼和摘要。
  - `概念/`: 分析方法论概念（如描述统计、回归、控制图等）。
  - `实体/`: 科室、疾病、核心指标等业务实体。
  - `方法论/`: 分析框架（如 DRG 分析、DIP 分析、综合绩效评估等）。
  - `报告/`: 基于多文档综合生成的深度分析报告。
  - `资产/`: 图谱、模板、配置等辅助资源。
- `.obsidian/`: Obsidian 知识库配置文件。

## 如何浏览与导航 (How to Navigate)
1. **入口文件**：建议从 `index.md` 开始阅读，它提供了整个知识库的分类汇总索引。
2. **推荐工具**：强烈建议使用 [Obsidian](https://obsidian.md/) 软件以 Vault（库）的形式打开本项目根目录。Obsidian 能够完美渲染文档间的双向链接（`[[双链]]`），帮助您可视化知识图谱。
3. **插件支持**：知识库的设计兼顾了 Obsidian 的 Dataview 插件。配合该插件，您可以更好地利用文档的 YAML frontmatter 数据进行动态查询和视图展示。
4. **健康检查工具**：本项目提供了一个简单的 Python 脚本用于进行知识库的健康度检查，运行 `python lint.py` 即可检查孤立页面（没有被引用的页面）和实体页面的格式问题。

## 如何与您的 LLM 结合使用 (How to Use with Your Own LLM)
本项目的核心特色在于与具备本地文件访问能力的 LLM Agent（如 Claude Code）配合使用，实现知识的半自动化管理：
1. **阅读规则**：请让您的 LLM 代理首先阅读并遵循项目根目录下的 `CLAUDE.md` 文件。该文件是知识库的系统提示词（System Prompt），详细定义了领域核心概念、标准维护流程（Ingest, Query, Lint）以及命名和状态规范。
2. **增量维护**：您可以将新的运营分析报告放入 `raw/` 目录下，并指令您的 LLM 代理：“请按照 `CLAUDE.md` 中的 `Ingest` 流程摄入这个新文档”。代理将自动读取内容、提取结构化数据、生成新的 `来源` 页面，并与现有的 `概念` 和 `实体` 建立双向链接网络。

## 环境要求 (Prerequisites)
要完整体验和维护此知识库的工作流，您需要：
- **Obsidian**: 用于浏览、检索知识库，呈现文档间的双向链接网络。
- **Python**: 用于执行解析脚本（如 `python-docx`），以便从 `raw/` 目录中的文档提取纯文本内容供 LLM 分析。
- **LLM Agent**: 例如 Claude Code 或其他具备文件读写和执行权限的 AI 代理工具，它是执行分析、归纳和自动化维护知识库的大脑。

## 该知识库对撰写分析报告的巨大帮助 (How it helps writing reports)

本知识库本质上是一个**“活的”医院运营与病种分析智库**。对于实际撰写一份《医院运营分析报告》或《某科室 DRG/DIP 病种分析报告》来说，它能提供全方位的支持：

### 1. 提供标准化的分析框架（方法论指引）
当面对复杂的 HIS/病案/医保数据时，知识库中的 `wiki/方法论/` 目录提供了最佳导航。例如沉淀的“DIP三层分析模型”（宏观定性盘点、中观波士顿矩阵定位、微观费用定因），您可以直接照搬搭建报告骨架，明确从医疗服务能力、质量安全到财务经济的标准化评估模块。

### 2. 精准的对标数据与历史痛点（科室/病种基线）
`wiki/实体/` 目录记录了各科室（如呼吸科、消化内科等）的历史核心指标和痛点。撰写新报告时，可直接检索相关科室实体页，追踪“耗材剪刀差”、“四级手术占比波动”等历史问题的改善情况，并通过 Dataview 拉取全院标杆对比（Benchmarking）。

### 3. 丰富的高阶数据可视化方案（图表武器库）
一份优秀的运营报告离不开清晰的图表。知识库收录了针对医疗数据特性的可视化方法：
- **科室竞争力评估**：波士顿矩阵、三维气泡图。
- **费用异常与分布**：用箱线图抓取离群极高费用病例，用云雨图/小提琴图展示同病同治的费用差异（变异系数 CV）。
- **多维度归因**：用森林图直观展示导致超长住院或超额亏损的关键影响因素。

### 4. 规范统一的指标定义（避免业务歧义）
`wiki/概念/` 明确了“组内变异系数(CV)”、“病种倍率”、“相对权重(RW)”、“药耗占比”等精确定义和计算逻辑。确保报告中的专业术语与全院管理口径一致，避免业务科室对数据统计逻辑的质疑。

### 5. 提供解决问题的管理建议（从“看数据”到“做决策”）
知识库从大量摄入的报告中提炼了具体的管理动作。当报告发现“某病种持续亏损”时，不仅能指出亏损，还能从中找到如“优化临床路径”、“规范病案首页并发症填写”、“推进日间手术转化”等对策参考，让报告具备真正的**管理落地价值**。

### 6. LLM 自动化生成的完美底座（高质量的上下文）
由于知识库是结构化的（Markdown + YAML 元数据 + 双向链接），它极其适合配合大模型使用。您只需提供新的原始数据，并附带指令：“请参考 `wiki/方法论/DIP分析.md` 的框架和 `wiki/实体/神经外科.md` 的背景，为我起草神经外科本月运营分析报告的大纲”，大模型就能迅速理解上下文，写出极度贴合医院业务习惯的高质量报告。

## 读者指南：如何“榨干”本知识库的价值 (How to Use This Repository)

为了让不同技术背景的用户都能从本知识库中获益，我们总结了**“三重境界”**的使用方法。您可以根据自己的需求和工具熟练度，选择最适合的方式：

### 第一重境界：作为“纯读者”在线查阅（获取方法论与现成经验）
这是最简单直接的用法。您无需安装任何软件，直接在 GitHub/GitLab 网页端浏览知识库的分类文档：
- **寻找方法论与分析框架**：直接阅读 `wiki/方法论/` 目录，学习如何搭建 DIP/DRG 盈亏分析模型、科室绩效评估体系等。
- **借鉴图表与可视化灵感**：参考总结的高阶图表库（如波士顿矩阵定位科室竞争力、用森林图做多维归因），将这些点子直接“抄”进您的 PPT 或微信推文里。
- **获取现成经验**：翻阅过往的分析报告和业务痛点总结，快速了解医院运营的共性问题及应对策略。

### 第二重境界：作为“Obsidian 玩家”沉浸式漫游（构建私人医疗图谱）
如果您希望建立结构化的知识体系，推荐您将本项目克隆到本地，并使用 **Obsidian** 打开：
- **可视化知识漫游**：利用 Obsidian 的 **Graph View（关系图谱）**，直观地看到“呼吸科”、“DIP 亏损”、“平均住院日”等节点如何相互交织，发现跨科室、跨病种的隐藏关联。
- **动态数据看板**：配合 **Dataview 插件**，您可以像写 SQL 一样查询文档属性。例如，动态拉取全院“盈亏金额 < 0 且 药耗占比 > 30%”的劣势病种列表，形成实时更新的业务看板。
- **打造私人智库**：在本地不断补充您自己医院的指标定义、科室属性，构建完全私有化的医疗数据分析大脑。

### 第三重境界：作为“AI 时代分析师”驱动 LLM 自动化（打造全自动外脑）
这是本知识库的终极玩法——将它与大型语言模型（如 Claude）深度绑定，实现知识提取与报告生成的全自动化：
- **自动化摄入新知**：将您自己医院的原始 docx 报告直接扔进 `raw/docx/` 目录。
- **AI 驱动构建 Wiki**：将 `CLAUDE.md` 作为 System Prompt，运行预设的 LLM Agent（如利用 `ingest.py` 脚本）。Agent 会自动阅读长文档、提取核心指标、生成结构化的来源页，并自动更新知识库的索引与双向链接。
- **跨文档智能查询**：无需手动翻找，直接向 LLM 提问：“基于知识库内容，综合分析我院近三个月外科系统的控费痛点。” Agent 会自动跨文档检索检索并输出深刻洞见，真正成为您的全自动“运营外脑”。
